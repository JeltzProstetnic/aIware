## Tracked-changes / review PDFs (latexdiff) — S268 recipe
- **Tracked-changes PDF (v_old→v_new):** `latexdiff old.tex new.tex > diff.tex`, then pdflatex×2 + bibtex + pdflatex into `tmp/`. Baseline = `git show <commit>:paper/full/latex/paper.tex`; new = current `.tex`. Build inside a copy of the paper's `latex/` dir (figures + `references.bib`).
- **Overflow fix (the recurring "blue text runs off the page"):** default `UNDERLINE` markup uses `ulem` `\uwave`, which defeats line-wrapping. Use `latexdiff --type=CFONT` (color, no underline) + inject `\setlength{\emergencystretch}{3em}\sloppy\hbadness=10000` before `\begin{document}` → 0 overfull.
- **"Only what's now in the paper" single-color view (MG's preferred review form):** run `latexdiff`, then in preamble `\renewcommand{\DIFadd}[1]{\textcolor{blue}{#1}}` + `\renewcommand{\DIFdel}[1]{}` (+ neutralize `\DIFaddbegin/end`,`\DIFdelbegin/end`) → additions one color, deletions dropped. (Yellow-highlight via `soul` FAILS on `\cite`/math — use colored text.)
- **CWD footgun:** never `rm -rf "$WORK"` while the shell CWD is inside `$WORK` — latexdiff then can't make temp files ("Could not create temp file… No such file"). `cd` out first.
- **Companion / fmt_formal md→PDF (unicode math σ/λ/≈/↔):** `build-md-pdf.sh` needs `-H paper/fmt_formal/unicode-header.tex` or it halts on the first unmapped char.
- **Zenodo:** new paper = `python3 scripts/zenodo-new-record.py <pdf> [--draft]` (token `.env.zenodo`, new concept DOI); version bump of an existing deposit = `scripts/zenodo-upload.sh`.
- **bioRxiv 2026 DOI prefix is `10.64898/`** (migrated from `10.1101/`) — do NOT "correct" a `10.64898` bioRxiv DOI back to `10.1101`.

## git-LFS phantom modifications — `Bin … -> 131 bytes` is NOT corruption (Session 220, recurring misread)
This repo's `.gitattributes` declares `*.pdf *.png *.svg *.epub *.docx … filter=lfs`. But several canonical binaries (notably `paper/cosmology/sb-hc4a.pdf`, `paper/cosmology_formal/sb-hc4a-formalization.pdf`) are committed as **raw blobs**, predating LFS activation — while `docs/*.pdf` etc. are proper LFS pointers. On any LFS-active machine git's clean filter then reports these raw-blob files as perpetually **modified**, and `git diff --stat` shows `Bin 298562 -> 131 bytes` (131 = the size of the LFS *pointer* the clean filter would emit). **This looks exactly like a truncated/clobbered file but the content is byte-for-byte intact.**
- **Diagnose, never assume corruption.** Before concluding any binary is damaged: (1) `stat -c%s <file>` — a real PDF is tens-to-hundreds of KB; (2) `sha256sum <file>` vs `git cat-file blob HEAD:<file> | sha256sum` — equal = zero real change; (3) `git lfs status` — a line `(Git: X -> File: X)` with **equal OIDs** is a phantom artifact, `(LFS: X -> File: Y)` with **differing OIDs** is a genuine rebuild.
- **`Bin <big> -> 131 bytes` in `git diff --stat` ≠ corruption** on this repo — it is the LFS-pointer size of a raw-blob binary. Never `git checkout HEAD -- <file>` "to restore" a file whose worktree sha already matches HEAD (it does nothing and reinforces the false alarm).
- **Permanent reconciliation** (so they stop showing as modified) is tracked as **`AIW-78`** — either `git add --renormalize` to migrate them into LFS (verify the LFS objects push to BOTH remotes; origin is a filtered public mirror) or exempt these paths from the LFS filter. The Session-216 `--assume-unchanged` workaround is **non-durable** (local-only git state — lost on checkout/reset/fresh clone), which is why the phantom modifications keep returning; only the renormalize is a real fix. (Committing a freshly rebuilt `sb-hc4a.pdf` during AIW-81 will reconcile that one file as a side effect, since LFS is now active.)

## Build pipelines
- **Full FMT:** source `paper/full/latex/paper.tex` (hand-maintained). Copy `latex/` → `tmp/build-full/`, run `pdflatex ×3` + `bibtex`. `bibtex` must run with `dangerouslyDisableSandbox` (sandbox blocks `.bbl` writes). The `.bbl` already exists — bibtex is only needed if references change.
- **When revising:** update `.md` AND `.tex` in the SAME session (the `.md` is the human-readable source of truth; the `.tex` is the build source — `build_full_pdf.py` COMPILES the hand-maintained `.tex`, it does NOT generate it from the `.md`). Skipping the `.tex` mirror drifts silently: **S239+S240 shipped `.md`-only, leaving `.tex` two full sessions behind by S241** (the Casarotto 91.2%→100% fix + the entire AIW-101 Opus-triage were absent from `.tex`; building then would have shipped a v12 missing its own headline). **Before any FMT build, verify parity** — e.g. `grep -c "91.2" paper/full/latex/paper.tex` must be 0 (match the `.md`), or compare `git log -1` dates of the two files. If they've drifted, the port spec is `git diff <last-.tex-commit>..HEAD -- <the .md>`.
- **Formalization + cosmology-formal papers are md-BUILT (no hand `.tex`)** — `paper/fmt_formal/`, `paper/rim_formal/`, `paper/cosmology_formal/`, and the new `paper/fmt_permeability_criticality/` each carry a paper-local `unicode-header.tex` (uses `\newunicodechar`, pdflatex). Build with the DOCUMENTED command from each paper's `*.formatting-rules.md`, **NOT** the generic `scripts/build-md-pdf.sh` (which only injects `paper/_shared/latex-preamble.tex` and dies on undeclared Unicode like σ/λ/⊆/⟹/≡): `pandoc <in>.md -H <dir>/unicode-header.tex --pdf-engine=pdflatex -o <out>.pdf`. If a build fails on `! LaTeX Error: Unicode character …`, add a `\newunicodechar{X}{\ensuremath{\cmd}}` line to that paper's `unicode-header.tex`. (S245: extended the fmt_formal header with ⟹ ≡ ↓ ⊗ ⊕ ∪ ∩ ⊃ ⊇ ≪ … to build the demoted roadmap + the new extraction paper.) NOTE: the **parent cosmology** paper `paper/cosmology/sb-hc4a.tex` (unlike the formalization) IS a `.tex`, but as of S245 it is a **stale, abridged pandoc build missing whole sections + ~40 refs** — regenerate it from `sb-hc4a.md`, do not hand-patch (AIW/handover `docs/pending-book-ed2-implementation.md`).

## Review-copy presentation
- Compile submission-quality `.tex` PDFs for review. **Never** present weasyprint/pandoc markdown renders when a `.tex` build exists.
- **Highlight changed passages in yellow:** make a `tmp/` copy of the `.md` with the edits marked, compile that copy separately. Standard academic revision practice. For a **PDF** review copy use `<mark>` (LaTeX `soul`/`\hl`). For a **`.docx`** review copy, obey the two pandoc traps below.
- **`.docx` review build — two pandoc traps (RECURRING; root-caused twice, S248):** reusable generator `tmp/aiw107-kalk/make_review_docx.py`.
  1. **Highlight whole paragraphs with `[text]{.mark}` bracketed spans, NOT `<mark>…</mark>`.** A `<mark>` wrapping a *whole paragraph/heading* is parsed by pandoc as a raw-HTML block and the highlight is **silently dropped** — the text survives but `word/document.xml` has **zero `<w:highlight>` runs**. `[…]{.mark}` renders as `w:val="yellow"`. (Inline `<mark>` inside a line does highlight, but paragraph-level doesn't — don't rely on it.)
  2. **Normalize every `---` horizontal rule to have blank lines on BOTH sides before `pandoc md→docx`:** `text = re.sub(r'\n[ \t]*---[ \t]*\n', '\n\n---\n\n', text)` then collapse `\n{3,}`. A bare `---` immediately followed by a `.mark`ed heading (`---\n## [Kapitel N]{.mark}`) makes pandoc's `multiline_tables` read the `---` as a table border and **swallow whole chapters into a full-width single-column table** — the "thin table" bug where everything after page ~4 renders illegibly. (The `.tex`/PDF build's own converter tolerates `---\n##`; only direct pandoc→docx breaks. The manuscript has 16 such `---\n#` spots — do not rely on the source being clean.)
  - **VERIFY before delivering any review `.docx`:** `python3 -c "import zipfile;print(zipfile.ZipFile(F).read('word/document.xml').decode().count('<w:tbl>'))"` must be ~0 (only genuine tables like the 5-layer figure). A docx→md round-trip that shows `\## Kapitel N` escaped inside dashed table cells = the trap fired.

## Parallel text-revision agents
- **MAX 50–65 lines per agent.** Chunks of 200–300 lines cause context-limit failures (Session 97 lost 6/7 agents this way).
- Always use **Opus** for German revision — weaker models produce translationese.
- **NEVER run two large Workflow fan-outs concurrently (Session 253).** Launching a 60-chunk Fable translation while an 89-agent Opus Kalk scan was still running tripped server-side rate limiting ("Server is temporarily limiting requests — not your usage limit") that *silently killed 37 of the 89 Kalk agents* (the `.catch` turned each into an empty result). The per-workflow concurrency cap (~14) does NOT protect you across workflows — two at once ≈ double the request rate. **Serialize:** run one big translate/scan workflow to completion, then the next. Re-running the failed segments alone succeeds. A single ~90-agent workflow run alone is fine (ES/FR/PT Kalk did 90).

## Blind global/substring substitution — the `comgarra` trap (AIW-109)
S260's PT term-standardization ran a global `preensão → garra` swap; `preensão` is a substring of `compreensão` ("understanding"), so it corrupted `compreensão → comgarra` and `autocompreensão → autocomgarra` at 8 sites — non-words that nearly shipped, caught only by the S262 native-editor review, not by any check. `replace_all: true` (Edit tool) does the SAME plain-substring match as `sed s///g`, so the global "use Edit, never sed/awk" rule does NOT protect against this. Worst in morphologically rich languages (com+preensão); language-agnostic.
- **Before any global/`replace_all`/substring swap of a term, grep the OLD string and read every hit** (`grep -no "<old>" <file>`). If it appears inside a larger valid word, the global swap is BANNED — do context-anchored single `Edit`s instead.
- **Anchor or bound.** Anchor each `Edit` on unique surrounding text, or match word boundaries (include the leading/trailing space or punctuation), so sub-word hits can't match.
- **Verify after every bulk swap — two greps, both must pass:** (1) `grep -n "<old>" <file>` returns only the leftovers you intended (ideally 0); (2) `grep -Eno "[[:alpha:]]<new>|<new>[[:alpha:]]" <file>` returns 0 — the new string never appears glued inside a larger token (this is what catches `comgarra`). For the line-aligned manuscript set, also confirm `wc -l` = 2475 across all files before delivering.
- **Machine-enforced guard tracked as `AIW-113`** (automated check script).

## Build-level typography for translations (AIW-109, S263)
Some typography is wrong to bake into the source `.md` (it must stay 2475-line-aligned) — apply it at
BUILD time instead. Lives in **`scripts/typography_fixes.py`** (pure, idempotent, tested by
`scripts/test_typography_fixes.py`), wired into `build_book_epub_lang.py` (epub) +
`build_translation_interior_cjk.py` (print):
- **CJK emphasis → bold, content-aware.** The shared converter maps `*x*`→`\textit{}` and pandoc maps it
  to `<em>` = slanted, which is typographically wrong on Hanzi/Kana (often just renders upright = emphasis
  lost). Fix: `*X*`→bold **only when X contains a CJK codepoint**; pure-Latin emphasis (*Nature*, *C.
  elegans*, book titles) stays italic. `cjk_emphasis_md` (epub) + `cjk_emphasis_tex` (print `\textit`→`\textbf`).
- **FR EPUB spacing.** pandoc `smart` ALREADY curls French apostrophes (`l'`→`l'`) — verified, don't
  re-do. The real gap is French high-punctuation spacing (babel-french gives print this for free, pandoc
  does NOT for epub): narrow NBSP U+202F inside « » and before ; ! ? ; full NBSP U+00A0 before :. `fr_epub_typography`.
- **Edition marker is PRINT-only.** The "First/Second edition" line is on the print copyright page
  (`edition_line` in `build_book_pdf{,_de}.py`; `cfg["edition"]` in the two translation interior scripts).
  eBooks carry only `© 2026` — never add an edition line to an epub.
- **Print covers are spine-driven, not text-driven.** Spine = pages × 0.002252"; the cover scripts bake a
  `pages` value (`build_book_cover*.py`, `build_translation_covers_print.py`). A cover needs rebuild only if
  the interior page count moved from that baked value OR the cover's own front/spine/back text changed —
  the edition-marker flip does NOT touch the cover. Always re-run the AIW-60 visual QA gate after any cover rebuild.

## Horizontal overflow (Overfull \hbox) — MANDATORY build hygiene
**Recurring failure (Session 216):** long URLs/DOIs and long tokens run past the right margin in generated PDFs (title block through citations). Root cause — long URLs don't line-break by default, and pandoc's template lacks `microtype`/`emergencystretch`, so TeX lets lines overflow and emits only a *silent* `Overfull \hbox` warning that was never checked.

**Permanent fix — use the gated wrapper for ALL markdown→PDF builds (never hand-roll a bare `pandoc --pdf-engine` again):**
- `scripts/build-md-pdf.sh <in.md> <out.pdf> [pandoc args]` — always includes `paper/_shared/latex-preamble.tex` (xurl + microtype + emergencystretch + tolerance) and **fails (exit 3) if any `Overfull \hbox` > 2pt**.
- `scripts/check-pdf-overflow.sh <build.log> [pt]` — standalone overflow gate; run on the `.log` of ANY build (incl. hand-maintained `.tex`) before presenting a PDF.
- Long author/affiliation lines → use a `\thanks{}` footnote (`author: "Name\\thanks{affiliation, ORCID, email}"`); `\author` does not wrap and overflows.
- **Rule: never present a PDF without a clean overflow check.** For hand-maintained canonical `.tex`, copy the lines from `paper/_shared/latex-preamble.tex` if its log shows overfull boxes.
- **The BOOK pipeline (`tmp/build_book_pdf*.py`, `build_translation_interior*.py`) is a SEPARATE LaTeX builder — the paper gate above does NOT cover it, and it hit the exact same bug (AIW-109 S264: KDP rejected ES/FR/IT/PT "text outside the margins" — long GitHub URL + long Romance words + slash-joined pairs).** `build_book_pdf.py` now carries the fix (`\emergencystretch=4em`, `\tolerance=3000`, `\hbadness=10000`, `\usepackage{xurl}`, and a break-after-slash rule in `escape_latex`: `(?<=\w)/(?=\w)`→`/\allowbreak{}`); `build_book_pdf_de.py` already had loose tolerance so DE never overflowed. **Gate EVERY KDP interior with `python3 scripts/check_pdf_margins.py <pdf>…` before upload** — recto/verso-aware, exit 1 if any content is >5pt past the margin (≤5pt = optical punctuation hang, KDP-safe). Fable/visual reviews SAMPLE pages and will NOT catch per-page overflow; only this gate does. KDP's own error text cites "insufficient gutter (≥0.5\")" but the geometry is inner=0.875" — the real defect is always the overflow, not the gutter.
- **The gate checks BOTH axes — VERTICAL overflow is a distinct second failure (S264):** a wide table that is too tall for one page runs off the BOTTOM margin because `tabularx` does not break across pages. Two traps: (a) the Appendix hierarchy table's nice "two-page spread" was gated on the *English* header string, so translated copies silently fell through to the general non-breaking `tabularx` and overflowed; (b) `tabularx` never page-breaks regardless. **Fix: the general table path uses `xltabular` (tabularx X-columns + longtable paging) with `\midrule\endhead`, so tall tables split across pages with a repeating header** (set `\small`/`\footnotesize` WITHOUT a `{..}` group — longtable must not sit inside one). `check_pdf_margins.py` flags vertical overflow too (excludes the footer folio). Never gate a table-bearing PDF on horizontal-only.
- **Raw LaTeX preamble tweaks MUST go through `-H <file>.tex`, NOT YAML `header-includes`** — pandoc markdown-processes metadata `header-includes` and mangles backslash commands (Session 216: title-spacing + `\geometry` silently didn't apply; two rebuilds wasted). For per-document layout, add `<doc-dir>/_preamble.tex` and pass `-H` as an extra arg to `build-md-pdf.sh`. **Verify layout changes by page count** (`python3 -c "import fitz; print(fitz.open(p).page_count)"`), not by eye — a 1-line orphan is usually a long reference wrapping the page break, fixed by recovering vertical space (e.g. `\geometry{margin=0.9in}`), not by title spacing.
- **Cover back-blurb LaTeX quotes — never hand-enter \'\' (S250 bug).** In a cover .tex, `\'\'` is two acute-accent commands, NOT a closing quote: it renders garbled `´´` AND swallows the rest of the paragraph. S250 — the DE paperback+hardcover back-blurb clipped at „Schwierige Problem", dropping the final line „Es war nur falsch etikettiert." Close quotes properly: EN ``…'' · German „…" via `\quotedblbase{}…\textquotedblleft{}` · Spanish «…» via `\guillemotleft{}…\guillemotright{}` (all T1-safe, no babel). **AIW-60 corollary:** QA cover text at READABLE resolution — render the back panel ≥150 DPI and read it; the thumbnail pass missed this clip.
